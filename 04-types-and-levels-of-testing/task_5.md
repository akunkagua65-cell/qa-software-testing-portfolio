## Использование ИИ для подготовки Grey-box чек-листа приложения «Найди и иди»

### 1. Запрос (Промпт) к ИИ
> **Промпт:** «Действуй как QA-инженер. Напиши черновик Grey-box чек-листа для приложения "Найди и иди". Приложение включает: поле ввода названия магазина, выпадающий список типов, кнопку "Поиск", карту с флажками и кнопку "Построить маршрут". Учти, что у нас есть полный доступ к базам данных (БД) магазинов. Сделай упор на сверку UI-данных с таблицами БД, валидацию статусов записей и корректность координат.»

### 2. Анализ результатов генерации ИИ
*   **Что ИИ учел хорошо:** Робот сразу добавил проверки на статус магазинов (активен/удален в БД) и валидацию координат для построения маршрута.
*   **Что ИИ упустил (Доработано вручную):** ИИ забыл про специфику работы при низком заряде батареи, работу с LocalStorage для восстановления маршрута и точную сверку расстояний через GIS-координаты. 

Ниже представлен финальный объединенный чек-лист, в котором ручные проверки дополненыGrey-box сценариями.

## Чек-лист для приложения «Найди и иди» (Методика Grey-box)

### ### ID Требования: SC21-01 — Поле ввода названия магазина

*   [ ] **Поле ввода названия магазина принимает:**
    *   [ ] Кириллические и латинские буквы (A-Z, А-Я);
    *   [ ] Пробелы и дефисы;
    *   [ ] Цифры;
    *   [ ] Специальные символы (@#$\%^&*<>...).
*   [ ] **Плейсхолдер в поле отображается корректно:**
    *   [ ] Появляется после загрузки страницы;
    *   [ ] Видим на всех платформах (моб./десктоп);
    *   [ ] Исчезает при вводе первого символа;
    *   [ ] Появляется снова при полном удалении текста.
*   [ ] Ввод $\ge$ 2 символов $\rightarrow$ кнопка «Поиск» становится активной.
*   [ ] **История поиска:**
    *   [ ] Сохраняется последний ввод;
    *   [ ] Сохраняется последний ввод после перезагрузки страницы.
*   [ ] Ввод 1 символа $\rightarrow$ поиск по магазинам не предлагает варианты;
*   [ ] Ввод только пробелов (2 пробела) $\rightarrow$ поиск по магазинам не предлагает варианты;
*   [ ] Пустое поле + нажатие Enter $\rightarrow$ поиск по магазинам не предлагает варианты;
*   [ ] Попытка вставки большого объема текста (1000+ символов) $\rightarrow$ приложение не зависает.
*   [ ] **[Grey-box]** Введённое название «Пятёрочка» возвращает корректный список, соответствующий записям в БД.
*   [ ] **[Grey-box]** Ввод заведомо несуществующего названия (например, «Zzz999») $\rightarrow$ убедиться, что нет результатов, и в БД тоже нет соответствующих записей.
*   [ ] **[Grey-box]** В истории поиска отображаются только успешные запросы, по которым реально есть магазины в БД.

---

### ### ID Требования: SC21-02 — Поле выбора типа магазина

*   [ ] **Поле выбора типа магазина:**
    *   [ ] Одиночный выпадающий список;
    *   [ ] Содержит 3 значения: «Продуктовые магазины», «Магазины стройматериалов», «Аптеки»;
    *   [ ] При выборе одного из значений список закрывается;
    *   [ ] Выбранное значение отображается в поле;
    *   [ ] Можно изменить выбор на другой вариант;
    *   [ ] Одновременно может быть выбран только один тип магазина;
*   [ ] **Плейсхолдер в поле отображается корректно:**
    *   [ ] Появляется после загрузки страницы;
    *   [ ] Текст: «Выберите тип магазина»;
    *   [ ] Цвет: #888888;
    *   [ ] Видим на всех платформах (моб./десктоп);
*   [ ] При невыбранном значении кнопка «Поиск» остаётся неактивной;
*   [ ] Список не допускает ручного ввода (только выбор одного из 3 типов);
*   [ ] **[Grey-box]** Количество магазинов по каждому типу на UI соответствует выборке в БД.
*   [ ] **[Grey-box]** Если в БД нет магазинов нужного типа $\rightarrow$ UI корректно отображает отсутствие флажков.

---

### ### ID Требования: SC21-03 — Кнопка «Поиск»

*   [ ] **Кнопка не активна:**
    *   [ ] После загрузки страницы;
    *   [ ] Если поле ввода названия магазина и поле выбора типа магазина — пустые;
    *   [ ] При удалении введённого текста в поле название магазина;
    *   [ ] При сбросе типа магазина.
*   [ ] **Кнопка активи
руется, если:**
    *   [ ] Введено $\ge$ 2 символов в поле названия магазина;
    *   [ ] Или выбран тип магазина из списка.
*   [ ] При нажатии на кнопку при активных полях $\rightarrow$ выполняется поиск.
*   [ ] При неактивной кнопке $\rightarrow$ клик не вызывает действия.
*   [ ] **Корректное отображение результатов успешного поиска на карте:**
    *   [ ] Отображаются флажки (иконка 📍) с названиями найденных магазинов;
    *   [ ] Каждый флажок содержит подпись с названием;
    *   [ ] Флажки размещены точно в местах магазинов;
    *   [ ] Если пользователь меняет фильтр $\rightarrow$ флажки обновляются;
    *   [ ] При пустом результате поиска на карте не отображаются флажки;
    *   [ ] Карта поддерживает стандартные действия:
        *   [ ] Зум с помощью прокрутки мыши (десктоп);
        *   [ ] Перемещение карты — перетаскиванием;
*   [ ] **[Grey-box]** Количество флажков на карте после поиска = количеству записей, полученных по запросу к БД.
*   [ ] **[Grey-box]** Проверка, что отображаемые магазины действительно «активные» (не помечены как удалённые/неактуальные в БД).

---

### ### ID Требования: SC21-04 — Кнопка «Построить маршрут»

#### Позитивные сценарии
*   [ ] При вводе корректного названия существующего магазина:
    *   [ ] Появляется результат поиска.
    *   [ ] После выбора флажка магазина на карте — кнопка становится активной.
    *   [ ] При нажатии на кнопку — строится маршрут до магазина.
*   [ ] При выборе типа магазина:
    *   [ ] Кнопка становится активной.
    *   [ ] При нажатии — строится маршрут до ближайшего магазина соответствующего типа.
*   [ ] При нажатии на активную кнопку:
    *   [ ] Меняется цвет фона на `#586d73`;
    *   [ ] Меняется текст на «Отменить маршрут».
*   [ ] При повторном нажатии на кнопку:
    *   [ ] Маршрут удаляется.
    *   [ ] Кнопка возвращает цвет `#ffffff` и надпись «Построить маршрут».
*   [ ] **[Grey-box]** Координаты маршрута на UI полностью совпадают с координатами из БД.

#### Негативные сценарии
*   [ ] **Кнопка неактивна:**
    *   [ ] Пока пользователь не выбрал магазин на карте.
    *   [ ] Если название магазина не распознано или пустое.
    *   [ ] Если тип магазина выбран, но нет ни одного подходящего магазина поблизости.
*   [ ] При нажатии на неактивную кнопку $\rightarrow$ Не выполняется никаких действий.
*   [ ] Ввод несуществующего названия магазина $\rightarrow$ Кнопка неактивна, маршрут не строится.
*   [ ] **[Grey-box]** Если координаты точки назначения в БД отсутствуют/null $\rightarrow$ маршрут не строится, появляется ошибка на UI.

#### Альтернативные сценарии
*   [ ] Пользователь выбрал тип магазина, затем изменил его $\rightarrow$ маршрут перестраивается.
*   [ ] Пользователь сначала построил маршрут, потом сменил выбор $\rightarrow$ отображается новый маршрут.
*   [ ] Пользователь очистил поле ввода/снял выбор $\rightarrow$ кнопка деактивируется.
*   [ ] **Обновление страницы:**
    *   [ ] Кнопка и маршрут возвращаются в начальное состояние.

---

### ### ID Требования: SC21-05 — Область карты

*   [ ] **Карта отображается до построения маршрута:**
    *   [ ] Показывает текущую геолокацию пользователя;
    *   [ ] Масштабирована по умолчанию на текущий регион;
    *   [ ] Имеет стандартные функции управления (зум, перемещение).
*   [ ] Область карты отображается после загрузки приложения:
    *   [ ] На экране телефона занимает ровно ~50% по высоте;
    *   [ ] Не перекрывает другие элементы интерфейса.
*   [ ] **Построение маршрута:**
    *   [ ] Маршрут строится, только если выполнены условия SC21-04:
        *   [ ] Либо выбран конкретный магазин на карте;
        *   [ ] Либо выбран тип магазина (и маршрут построен до ближайшего);
    *   [ ] Построенный маршрут отображается как линия от текущего положения до магазина;
    *   [ ] Отображаются метки начальной и конечной точек.
*   [ ] **Отмена маршрута:**
    *   [ ] Кнопка «Построить маршрут» меняется на «Отменить маршрут»;
    *   [ ] При нажатии «Отменить маршрут» маршрут
удаляется с карты;
    *   [ ] Маршрут не удаляется другими способами (например, повторным поиском или сменой фокуса).
*   [ ] **[Grey-box]** Проверка, что маршрут визуально отображается в UI именно по тем координатам, что указаны в БД.
*   [ ] **[Grey-box]** Сравнение длины маршрута на экране с вычисленной через GIS по координатам из БД.

---

### ### ID Требования: SC21-06 — Общие требования к работе приложения

#### Позитивные сценарии
*   [ ] **При повторном открытии приложения:**
    *   [ ] Если был построен маршрут и не был отменён — он восстанавливается на карте;
    *   [ ] Маршрут отображается с теми же точками (от и до), что и до закрытия;
    *   [ ] Флажки и линии маршрута видны сразу без доп. действий;
    *   [ ] Кнопка отображается как «Отменить маршрут» (не «Построить маршрут»);
*   [ ] **Отключение точной геопозиции при низком заряде:**
    *   [ ] Плавный переход между режимами (точный/неточный) — без перезагрузки карты;
    *   [ ] При достижении порога заряда (например, $\le$ 10%) точная геолокация отключается;
    *   [ ] Построение маршрута всё ещё возможно, но может быть менее точным;
    *   [ ] При отключении геолокации поведение интерфейса не вызывает ошибок;
    *   [ ] При восстановлении заряда выше порога (например, $\ge$ 20%) точная геолокация включается обратно.
*   [ ] **[Grey-box]** При повторном запуске приложения маршрут восстанавливается — убедиться, что в БД или localStorage есть сохранённая точка маршрута.
*   [ ] **[Grey-box]** Проверка, что при низком заряде GPS переключается на приблизительные координаты, но маршрут строится до той же точки в БД.
